# 架构讨论与验证路线

## 当前方向

用户于 2026-10-11 确认优先测试 **Dear ImGui + imgui-node-editor**，理由是依赖少、定制灵活及已有类 UE 蓝图实现，详见 [D001](decisions.md)。跨平台是明确后续目标，优先降低重复开发成本。

React／Tauri 与 Avalonia 保留为候选，当前不继续作为优先原型；最终产品框架尚未定案。

## Dear ImGui 路线的收益与成本

| 关注点 | 收益 | 需要验证的代价 |
| --- | --- | --- |
| 依赖与接入 | 核心自包含，官方提供平台／渲染后端；原型只链接两个 UI 库和 Windows API | 窗口、字体、对话框、发布和生命周期仍由应用负责，少依赖不等于少产品工作 |
| 蓝图编辑 | 节点内容／端口可定制，提供拖动、缩放、选择和连线交互 | 工作流模型、类型、调度、函数／子图和 MCP 对等仍需自行实现 |
| 原生预览 | 可显示渲染后端纹理，适合工具型 UI 与图形管线接入 | 真实捕获纹理的所有权、跨设备、颜色与叠层仍需验证 |
| 跨平台 | 可更换平台／渲染后端，UI 代码有复用空间 | 捕获、输入、权限及图形资源不同；Windows 原型不能证明其他平台可用 |
| 面向普通用户 | 可高度定制简单预设和工具工作区 | 官方定位偏开发工具，不提供完整国际化与无障碍；系统交互、文本、键盘和 DPI 需实测 |

依据：[Dear ImGui 定位与限制](https://github.com/ocornut/imgui)、[官方后端](https://github.com/ocornut/imgui/blob/master/docs/BACKENDS.md)、[节点编辑器](https://github.com/thedmd/imgui-node-editor)。

## 当前原型与实际发现

- 原型使用原版 ImGui 1.90.9 和节点编辑器 0.9.4 对应固定提交；构建入口、精确版本与证据见 [Desktop](modules/desktop.md)，不是“已支持最新版本”的结论。
- 上游 Blueprints 示例依赖额外布局分支；原型采用原版控件验证接入，不整体移植该示例，也不把分支维护成本隐去。
- 节点编辑器的键盘兼容函数与 ImGui 旧接口产生重复符号；本组合通过 `IMGUI_DISABLE_OBSOLETE_KEYIO` 解决，未修改上游源码。升级需重新验证，不能只看 README 的最低版本。
- 节点库解决画布交互，不解决运行引擎。固定样例连线和共享参数已可交互，函数／子图执行和 MCP 状态同步还没有证据。
- 原型连续绘制 UI，闲置 CPU／GPU、后台窗口和设备丢失行为尚未做完整测量；不因 UI 显示 60 fps 宣称录制性能达标。
- 字体／UTF-8 字符串不等同于完整多语言；中文路径、IME、复杂文字与本地化资源仍需验证。MCP 功能接口也不能替代屏幕阅读器或 OS 无障碍树。

## 下一步验证议题

继续检查简单预设易用性、节点编辑与参数模型、窗口缩放／DPI、文本／路径输入，以及真实捕获／编码运行中的预览。检查 UI 和 MCP 能否共享产品能力，避免将运行逻辑绑在绘制循环里。这些是验证目标，不是提前固定实现规则。

## 仍待选择

| 议题 | 主要取舍 |
| --- | --- |
| 媒体后端与核心语言 | 系统 API／媒体库和语言互操作成本；不因 UI 使用 C++ 就自动冻结整个业务核心 |
| MCP 与宿主 | 本地 HTTP／stdio、连接现有应用或独立运行的状态与启动成本 |
| 存储与验证 | 文件／数据库、压缩／无损、时间／事件对齐的查询、容量及可信度 |
| 部署与平台 | 支持的系统／架构、安装包和后续平台次序 |

候选讨论与已确认决策分开，验证结果只证明实际测试过的范围。
