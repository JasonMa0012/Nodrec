## D001：优先测试 Dear ImGui + imgui-node-editor

- 日期：2026-10-11。
- 选择：先测试该 UI 路线，替代此前 React／Tauri 优先验证建议；这是原型方向确认，不是最终产品框架定案。
- 用户确认依据：“我希望先测试Dear ImGui + imgui-node-editor的路线”，主要看中依赖少、可自定义程度高及已有类 UE 蓝图实现。
- 预期收益：工具型 UI、节点交互和原生纹理预览可在 C++ 环境中验证，减少首个原型的跨语言接入。
- 代价与边界：普通用户交互、窗口／图形后端、复杂文本、无障碍和依赖升级仍有成本；蓝图示例不等同于工作流执行引擎。
- 验证情况：Windows UI 原型已构建并运行，证据见 [Desktop](modules/desktop.md)；真实录制／回放／编码、MCP、其他平台和完整多语言仍未验证。

## D002：以 React + Tauri 开始实现现代桌面 UI

- 日期：2026-10-12。
- 选择：用户明确要求开始使用 React + Tauri；当前节点画布使用 React Flow。
- 依据：用户希望获得接近草图和 Codex 的一体化标题栏、折叠导航、页面切换与可定制节点 UI，并接受替换 ImGui 节点编辑器。
- 范围：这是当前界面实施路线，不代表录制／媒体核心语言、最终产品架构或发行方案已冻结；原 ImGui 原型保留作参考。
- 代价：Tauri 依赖 Rust 构建环境和系统 WebView；Web UI 会增加 WebView 进程内存。用户希望 UI 私有工作集控制在 200 MB 内，必须在实际运行后测量，不能从较小安装包推断。跨平台录屏和输入仍需原生适配。
- 验证：TypeScript、Vite 前端和 Tauri Release x64 构建已通过；Tauri 窗口运行、内存和真实交互尚待验证，见 [Desktop](modules/desktop.md)。

## D003：蓝图文件与第一版运行核心

- 日期：2026-10-14。
- 选择：一个蓝图保存为单个 UTF-8 `.nodrec.json` 文件，使用版本号为 1 的 JSON 文档；内置及用户目录位于应用程序 exe 旁的 `blueprints/builtin/` 和 `blueprints/user/`。
- 依据：用户选择 JSON、Rust 运行核心、初始化 Event 注册总控按钮、同图表达控制与媒体流、单实例运行，并确认内置蓝图可删除且启动不补充缺失文件。
- 生命周期：程序启动只扫描已有文件，不创建目录、不恢复缺失或已删除内置蓝图。开发／发布构建把仓库模板复制到对应 exe 旁缺失的位置；保存始终写回蓝图原目录，删除移动到 `.trash/` 供本次运行撤销。
- 界面：On Initialize 的 Register Control 节点注册主按钮，Register Control Menu 节点逐项注册菜单；路径如 `Start`、`Start/Start after 3s` 表达层级，并由运行时组装。节点参数通过可视控件编辑；整数 Order 控制总控栏顺序，相同值保持注册顺序。旧配置缺少 Order 时按注册序号提供内存默认值；旧递归菜单加载时迁移为路径节点。按钮可配置图标、文字和顺序。Blueprint Details 随内容调整高度，可拖动宽度并覆盖全宽节点画布。
- 运行：Rust 负责类型化节点目录、图校验、执行线／值线／媒体流和运行状态；当前用模拟帧与日志替代捕获、编码和写入。操作录制配置仅作预览，不能启动。
- 取舍：JSON 结构清晰，前后端无需额外解析器；与 JSONC 相比不支持注释，与 YAML 相比减少缩进和隐式类型歧义。单文件完整保存参数、布局和工作流，但大型媒体／运行产物不放进此格式。
- 验证：Rust 存储与运行单测、React 模型测试、Release WebView 录制流程已通过；真实采集／编码、操作记录、回放、函数和子图仍未验证或实现。

MCP、差异算法和发行方式仍未确认。原型使用的 C++14、MSBuild、Win32／DX11 及兼容版本组合仅用于原型验证，不自动成为永久技术栈。

## D004：第一版真实录屏管线

- 日期：2026-10-21。用户比较路线后选择 Windows 原生 API，并明确要求实施完整录屏计划。
- 选择：WGC→D3D11→Media Foundation→MP4；保留区域／捕获／H.264／写入节点拆分，由 Start／Pause／Resume／Stop 管理原生持续流。首版单显示器全屏／区域、无声，区域仅开始前调整。
- 硬件优先，允许用户明确选择软件 H.264；硬件失败不得自动切换 CPU。以 1080p60 为主、兼测 1440p60，快速停止及低游戏开销必须实测。
- 代价：Windows 和驱动相关的资源生命周期、格式协商及硬件兼容性；硬件编码不保证 GPU 满载时没有额外帧时间开销。Bandicam 只作性能对照，当前未宣称达到同等性能。验证事实见 Capture、Media Output 和验收文档。
