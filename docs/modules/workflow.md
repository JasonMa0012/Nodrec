# Workflow：节点工作流

## 当前实现

正式工作流格式、运行时和执行引擎尚未实现。UI 原型提供一个可编辑的演示图：

- [graph.h](../../prototypes/imgui/graph.h)定义稳定的节点、端口和连线 ID，端口类型、方向和节点目录；[ui.cpp](../../prototypes/imgui/ui.cpp)负责节点目录、节点内容及与画布的交互，两者分离。
- 示例目录包括开始录制事件、选择屏幕区域、采集屏幕／音频、编码、写入和唯一输出路径节点。屏幕／音频节点按钮只模拟状态。
- 画布接入上游 imgui-node-editor Blueprint 示例绘制器，支持添加／删除节点、移动、缩放、选择、连线增删。连接校验覆盖无效端口、方向、类型、自连和输入占用；删除节点会清除关联端口和连线。
- [ui_state.h](../../prototypes/imgui/ui_state.h)中的 Events 和 Functions 只保存可编辑元数据；参数通过变量显式暴露到卡片。它们没有事件调度、函数体、子图、执行数据或持久化格式。
- 自检验证连接规则、节点删除级联清理、卡片行列和宽度比例、固定状态及蓝图副本隔离。实际鼠标拖放连线、重排、缩放和列宽调整尚未实测。构建与快照证据见 [Desktop](desktop.md)。

## 职责与边界

Workflow 未来负责描述和执行节点、参数、事件、函数、子图和预设。Desktop 负责画布和卡片交互；Runtime 协调运行；各媒体与输入模块提供节点能力。当前演示图不定义产品接口或执行语义。

## 一期目标

- 屏幕／窗口／区域、音频、编码、写入和路径节点；参数可连接节点输出。
- 开始／每帧／结束事件，函数和子图支持预设复用。
- 在定义产品执行模型前，确认值／流／事件语义、类型规则、失败行为、运行版本及编辑历史。

## 验收

T01 尚未通过。仍需以实际工作流验证预设可编辑、无效图有解释、事件／函数／子图可复用，并确认 UI 与 MCP 使用同一产品能力；原型中的静态连线自检不替代这些验收。

## 未来规划

先用端到端工作流验证最小模型，再考虑调试、扩展节点和插件；避免未经验证就把工作流做成通用编程语言。
