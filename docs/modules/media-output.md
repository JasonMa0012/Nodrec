# Media Output：编码与写入

## 当前实现

Windows Media Foundation 已实现实时无声 H.264→MP4，入口为 `recording.rs`／`recording/windows.rs`：

- Hardware Auto 使用 `MFTEnum2` 按捕获适配器 LUID 枚举并激活硬件编码器，记录实际名称和适配器；要求 D3D11 输入，不隐式回退软件或跨适配器 CPU 拷贝。
- Software 显式使用系统 H.264 编码器，复用 GPU 转换，仅在编码入口回读 NV12；会增加 CPU 负担。
- CBR 0.1–200 Mbps（默认 20）、High Profile、2 秒 GOP、无 B 帧；24／30／60／120 fps，Source Size／1080p／1440p。设备实际不接受的配置在启动时报错。
- 压缩包复制到有界队列（最多目标帧率的 2 秒），由独立原生线程持续写 MP4。写入跟不上时明确失败；不丢弃已经编码的包。GPU 转换后显式 Flush，避免异步编码器读取旧黑纹理。
- 停止先关闭捕获并排空编码器，再等待 Sink Writer Finalize 和文件句柄释放；成功后用不覆盖目标的同目录 MoveFileEx 发布最终 MP4。录制中使用 `.partial.mp4`，失败保留并返回路径。编码器排空上限 10 秒；底层驱动／磁盘阻塞不承诺硬性停止期限。

## 职责与边界

编码节点转换图像／音频，写入节点生成本地视频；Storage 管理位置与产物关系。

## 一期目标

- 首版真实参数见当前实现；后续再按需求扩展质量模式、编码器和容器。
- 处理编码器输入／输出和容器组合，明确结束与部分失败结果。
- 待选择：系统 API 或媒体库、首批编码器／容器、硬件路径及默认质量。

## 验收

本机 `AMDh264Encoder` 与 `Microsoft H.264 (Software)` 均已生成可完整解码的 898×360 MP4，软件路径已测暂停／继续；AMD 1440p60 短录通过。Release 端到端区域录制停止约 7–8 ms，并验证已有最终文件不被覆盖；首帧已目视检查。长录制结果和性能边界统一记录在 [验收场景](../testing.md)。音轨、NVIDIA／Intel 和游戏负载未验证。
